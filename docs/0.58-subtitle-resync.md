# OpenNomi 0.58.0：重复短句复用与手动同步

本机 Google 翻译成功返回的短句可在内存中复用。缓存键同时包含源语言和完整原文，大小写、标点、换行的变化均不匹配；只复用非空成功结果，最多保留 32 条，原文和译文均不超过 1200 字符。命中仍作为一条新的讲话，保留字幕顺序、重复语句和近期译文，不抑制重复讲话。在线模型和 LibreTranslate 不使用这项缓存，避免复用带有不同上下文的回答。停止共享或关闭翻译客户端会清空；旧任务即使晚完成，也不能重新写入已清空的缓存。首次模型下载要求不变，不承诺具体的加速倍数或识别准确率。

视频字幕页显示待完成翻译的语句数量（包括当前请求）与等待显示的译文数量。字幕明显落后或一条失败语句挡住后续字幕时，可点击“重新同步当前声音”；积压时，悬浮菜单也提供该入口。这个操作是用户主动跳过：取消当前翻译，清空未完成语句和待显示字幕，丢弃旧识别器的未结束结果，重新建立当前共享的声音捕获。保留本次共享已经完成的近期译文，已安装模型继续使用，不重复请求屏幕共享权限。重新加载识别器需要时间，新捕获仍受播放器的声音捕获政策约束。

仍使用 0.57 的短停顿优先分段、有序字幕显示和 20 条近期译文。不会自动丢弃积压来制造低延迟；用户不点击同步时，保持原有顺序和失败重试。译文内容、准确率、手机实际延迟及蓝牙表现不作未经实测的保证。

版本代码 58，包名 `com.opennomi.android`，沿用 0.53–0.57 证书。验收包括缓存的语言/文本隔离、容量及清空后晚完成的任务，真实模型重复译文、离线重载，Android 10／13 实际无字幕播放器声音捕获、悬浮入口、手动同步后继续产生中文字幕、旧捕获的停止回调不影响新捕获，以及上一版画面资源停止顺序验证。完整备份与加密签名恢复流程沿用现有脚本。
