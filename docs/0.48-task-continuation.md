# OpenNomi 0.48：连续任务与恢复修复

本版保留 0.47 的 FishAudio 声音工作台、内部账号申请、独立朗读和回复接入。

## 多步骤控制

- 等待确认、同名应用选择或同名按钮选择时，保留原任务及剩余步骤。
  新目标不会悄悄覆盖它；可先说“取消任务”，再说新任务。
- 正在执行时说出的“确认执行”不进入等待队列。需要看到当前步骤的
  确认提示后，再单独说一次，避免提前的确认落到后面的操作上。
- 任务进入等待或暂停时，清空还没执行的后续排队指令。
  普通步骤仍依次执行，例如“打开相机，然后拍照，然后退出相机”。
- 页面切换超过等待时间，保留当前未执行步骤及剩余任务。回到目标应用，
  说“继续任务”恢复；不会重新执行已完成的步骤。
- 暂停任务后继续聆听，但不执行新操作；可说“继续任务”或“取消任务”。
  等待确认或选择的步骤不能靠“继续任务”绕过。

## 输入文字

“输入”和“打字”后面的未加引号文字都按完整内容输入。例如：

- “打字你好，然后退出应用”：输入“你好，然后退出应用”，不会退出应用。
- “请帮我输入你好，然后返回”：输入“你好，然后返回”，不会返回。
- 要在输入后继续操作，明确使用引号，例如：
  “打字“你好”，然后点击搜索”。应用解析器支持中文双引号“…”和英文双引号。

不闭合的引号会报告错误，整个指令不执行。输入不会自动发送；发送等控件
仍需单独确认。按钮与输入位置依赖目标应用提供的无障碍信息。

## 安装与验证范围

APK 延续原包名和原签名，可以覆盖安装。首次需要允许麦克风、相机及
无障碍权限，配置方式沿用 0.47。复杂任务仍需共享屏幕与可用视觉模型。

本轮验证任务等待、指令队列、文字解析、取消及恢复策略，并进行 Android
编译和界面检查。尚未连接你的小米 10 Pro / Android 13；系统识别服务的
中文支持、识别速度、真实第三方应用动作及后台保活仍需手机实测。
