# 0.39 changes and rationale

NOMI / AIRI remain the only two modes. The original 0.29 ball shape and emotion definitions are unchanged.

- The serial audio decoder reuses one 5760-sample PCM buffer. Before this change a new buffer was allocated for every incoming Opus frame. Microphone capture retains its separate buffer.
- Start playback after 120ms instead of 180ms of decoded audio. Short replies are force-started by the final drain.
- A TTS stop event triggers a FIFO drain that waits for all preceding audio commands and the actual AudioTrack playback head. The redundant fixed 150ms wait is removed. This follows the original protocol's documented audio-then-stop message order.
- The manual continuous-listening delay is 120ms instead of 200ms. The speaking state remains visible during this short handoff, avoiding an idle-state flash.
- Queued start can be cancelled while connecting. Background pause clears the queued start.
- Capture callbacks carry a turn generation before entering the UI loop so delayed endpoint/barge-in/error callbacks cannot affect a newly started turn.
- Reconnects share an HTTP dispatcher and connection pool. Timer setup and close are synchronized to avoid scheduling after shutdown.
- The breathing aura keeps its gradient brush and varies drawing alpha. Level bars avoid constructing a list on every draw.
- Ball taps use Android touch slop and ignore drags, multi-touch and cancelled touches. Destroyed WebViews ignore late readiness callbacks. The native fallback reuses its eye rectangle.

Primary references checked during this change:

https://github.com/78/xiaozhi-esp32/blob/main/docs/websocket.md
https://developer.android.com/reference/android/media/AudioTrack#setStartThresholdInFrames(int)

The changes reduce local overhead and fixed waits; they do not establish a measured reduction in server response time or guarantee real-device glitch-free playback on every network.
