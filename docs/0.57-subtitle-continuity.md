# OpenNomi 0.57.0：分段、字幕阅读和近期译文

连续讲话到达更快显示的 3.5 秒／完整语句的 5.5 秒目标后，不再立即强制结束。识别器优先等待至少 200 ms 的低声音能量与稳定识别文本，最多额外等 1.2 秒；原生停顿终点仍可更早结束。仅已结束的识别结果参与翻译，临时原文保持预览。背景音乐或连续讲话可能一直没有合适停顿，最终仍须分段，不能保证每个词或每个长句都完整。这是分段目标，不能当成端到端字幕延迟保证。

第一条译文就绪后立即显示。连续返回的译文进入有序展示队列，中文按长度保留 0.75–1.5 秒的基本阅读时间，实际切换还受轮询和手机调度影响。最多等待 2 条展示内容；展示队列满时暂缓继续翻译，已识别语句仍在原有队列等待，不替换已接受的未读译文。已识别队列仍为 12 条、积压时仍最多合并 3 条相邻原文；持续超负荷时可能拒收新语句，并显示提示。阅读时间可能增加积压时的显示延迟，视频播放过快时可降低速度。

新增“近期译文”：在翻译页选择该入口，或者点悬浮球菜单的“查看近期视频译文”。保留本次共享最近 20 条已成功翻译的原文与译文，包括重复讲话和识别提醒；只在应用内存暂存，不自动保存到碎片本或数据库，不自动导出。暂停视频字幕后可继续回看，停止共享会清空近期列表和当前字幕；新共享从空列表开始。可以手动清空列表或主动选择复制内容。

识别提示采用已知词置信度中的最低值，避免少数不确定的人名、数字等被高平均值掩盖。非法或缺失置信度不当成满分。置信度不是实测准确率；看原文和视频上下文仍很重要。视频运行期间暂时禁用文字试译和语言下载设置，避免同一手机翻译客户端切换语言、下载模型影响正在播放的字幕。

沿用包名 `com.opennomi.android` 和 0.53–0.56 发布证书，版本代码 57。首次准备模型仍需网络；播放器仍必须允许系统声音捕获。验证包括两种分段模式的真实独立播放器声音捕获、中文字幕、可见近期译文、暂停保留及停止清空，日语模型下载与离线重载，以及有序展示、取消和边界单元测试。Android 10／13 模拟器验收不代表真实手机、蓝牙耳机或视频内容的准确率与延迟测量。基本用法见 [0.56 文档](0.56-video-optimization.md)。每版完整归档安装包、测试报告、签名与密码加密副本，并从 GitHub 重新恢复核对。
